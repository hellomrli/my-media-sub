# v2.2.18 升级指南

Docker Compose 部署：

```bash
docker compose pull
docker compose up -d
```

WebUI 在线升级（「系统设置 → 版本更新 → 在线更新」）从本版本起会自行完成重启，不再需要手动重启容器——这是 v2.2.17 修掉的问题。

v2.2.18 不修改 JSON Store schema，可直接复用 v2.2.17 的 `data/`。本版本只改界面与前端布局，没有后端行为变更（新增了一个 `POST /api/jobs/clear` 接口）。

## 界面变了什么

### 工作台：卡片化仪表盘，一屏看完

原来的工作台把同一份信息说了三遍——hero 里的「追更中/已完结/运行中任务」、下面的 KPI 卡片、右侧的「待处理事项」互相重复，再加上一个占 330px 的装饰性大标题，1920×1080 的屏幕连一半内容都装不下。

现在的结构是：

- **概览与操作**：一行状态摘要 + 检查全部订阅 + 搜索资源
- **运行指标**：7 个紧凑指标格（追更中 / 已完结 / 失效订阅 / 后台任务 / 失败任务 / 未读通知 / 下载速度），点任意一格直接跳到对应筛选结果
- **面板区**：订阅看板、夸克网盘、自动化执行、最近活动

页面本身不再滚动：指标区按内容高度排布，面板区平分剩余高度，长列表只在卡片内部滚动。

**卡片可以自己排。** 右上角的「编辑工作台」进入编辑态，每张卡片带上移、下移、隐藏三个按钮，隐藏掉的卡片会出现在顶部编辑栏里，点一下加回来；也可以一键恢复默认。保存后写进 `dashboard_widgets` 设置。

**v2.2.17 之前保存过布局的用户不用重新配置**：旧的 `hero` 会映射为「概览与操作」，`operations` 映射为「夸克网盘 + 自动化执行 + 最近活动」，你原来的顺序会保留。

**订阅看板只显示追更中的订阅**，已完结的不再占位置。失效的订阅由「失效订阅」指标格标红，点它直接跳到筛选好的列表——不会因为不在看板里就被忽略。

### 系统设置：按使用逻辑重新分组

原来的「连接」一页塞进了夸克 Cookie、Aria2、TMDB、登录账号和保存目录五件事，找一个选项要滚半天。现在按「接入 → 运行 → 维护」拆成 7 个标签页：

| 标签页 | 放什么 |
|---|---|
| 夸克网盘 | 夸克 Cookie、账号健康、自动签到、保存目录 |
| 下载与元数据 | Aria2 配置与下载目录、TMDB |
| 自动化 | 订阅调度、安全自动换源 |
| 命名规则 | 规则中心、规则配置、样例预览 |
| 通知 | 推送事件、通知策略、推送渠道、渠道测试 |
| 高级与安全 | 登录账号、PanSou 与搜索默认项 |
| 版本更新 | 版本检查、指定版本切换、升级方式 |

每个标签页内部也从纵向堆叠改成了自适应多列，常用的几页现在都能一屏看完。

**旧链接不会失效**：`connections`、`maintenance`、`basic`、`push`、`rules` 这些老的标签页 id 都会自动映射到新页面，收藏的链接和 PWA 快捷方式继续可用。

### 下载任务：四类任务分页

正在下载、队列中、已完成、下载失败改成标签分页，每个标签带任务计数，一次只看一类。总速度和订阅关联数移到了工具栏那一行，省掉整行指标网格。

### 更新日历：压缩到一屏

工具栏收成一行，四个统计数字改为内联小标签，视图区填满剩余高度并在内部滚动。

### 活动中心：不再被推送派发刷屏

推送派发任务只是通知的投递动作，本身没有阅读价值，却因为每条通知都会产生一条而淹没整个列表——线上实测占任务总数的 **88%**（306 条任务里 268 条）。现在这类任务不在活动中心列出，通知本体照常展示。

同时新增了「清除日志」按钮：删除全部已完成、失败和已取消的任务记录（含归档），排队中和运行中的任务不受影响。

## 二进制部署

手动升级时必须同时替换归档中的整个 `static/` 目录——本版本几乎全是前端改动，只换二进制不会有任何变化。前端资源 URL 带 `?v=2.2.18`，Service Worker 缓存代次为 `v2.2.18-dashboard-cards-and-settings-1`。
