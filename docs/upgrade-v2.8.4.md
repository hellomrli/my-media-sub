# v2.8.4 升级指南

[返回文档入口](index.md) · [完整变更](../CHANGELOG.md)

v2.8.4 修复休眠或进程暂停后的自动检查停摆，完善夸克签到和设置重载，并包含未单独发布的 v2.8.3 手机日历修复。不改变 JSON Store schema 或既有 API 契约，可直接复用 v2.8.2 / v2.8.1 的数据与配置。升级前核对备份，保留 `data/`、`runtime/` 和原 `.env`。

## Docker Compose

在原部署目录执行：

```bash
docker compose pull
docker compose up -d
docker compose logs --tail=100
curl --fail http://127.0.0.1:56001/health
```

确认健康检查返回 `"version":"2.8.4"`。固定镜像版本的用户改为 `ghcr.io/hellomrli/my-media-sub:2.8.4`，再执行上述命令。

拉取镜像并重建容器可同步获取运行层系统补丁；WebUI 在线更新只替换程序和静态资源。不要删除数据卷或重新生成管理员密码。

## 独立二进制与在线更新

从 [v2.8.4 Release](https://github.com/hellomrli/my-media-sub/releases/tag/v2.8.4) 下载 Linux x86_64 归档及同名 SHA-256 文件，校验后停服，替换程序和**完整 `static/` 目录**，保留数据、配置与备份。操作参考 [发布包部署](deployment.md#使用-linux-x86_64-发布包)，在线更新信任配置见 [Docker 在线更新](docker-online-update.md)。

本版页面资源使用 `?v=2.8.4`，PWA 缓存代次为 `v2.8.4-scheduler-1`。重新加载旧页面；已安装的 PWA 收到更新横幅后点击“立即更新”。原有主题、订阅视图和工作台布局偏好继续保留。

## 行为变化与测试

1. 确认 `/health` 返回 `2.8.4`，原订阅、任务和设置仍在，执行一次“立即检查”验证自己的分享与转存流程。
2. 修改自动检查间隔，反复保存设置并启停自动检查：保存正常，后续只按最新配置执行。主机恢复后，错过多个周期只补跑一次，随后继续按配置间隔检查；已有任务不会因重载而并发执行。
3. 开启夸克自动签到并保存整点设置：仍按北京时间执行，错过当天时间后在恢复时补签；当天已有成功记录时跳过自动重复签到。手动签到仍可主动执行。
4. 在手机工作台打开日历周视图：每条排期占满一行，长剧名显示省略号，日历不超出卡片右缘；平板和桌面日历显示保持一致。
5. 核对自己的时区规则：日历与 Telegram 使用北京时间，推送静默时段与订阅星期规则使用宿主时区；API 时间继续使用 UTC RFC 3339，文件时间排序和数字时间戳保持兼容。

本地与 CI 回归使用临时数据和本地夹具，覆盖定时器暂停恢复、时钟调整、并发重载、日期兼容、手机 / 桌面浏览器以及旧发布二进制升级。真实夸克签到 / 分享、Aria2 下载、TMDB 查询和 Web Push 送达请在自己的部署中验证；门禁与实际云端产物核验见 [路线图](roadmap.md)。

本次发布提供 SHA-256 校验文件；`.minisig` 仅在发布工作流配置签名密钥时生成。已设置 `SELF_UPDATE_PUBLIC_KEY` 的客户端会拒绝无签名归档，遇到这种情况使用 Docker Compose 或独立二进制步骤升级。签名与信任配置详见 [Docker 在线更新](docker-online-update.md)。

## 回滚

停服后换回 v2.8.2 镜像或旧二进制与配套 `static/` 即可。不需要数据迁移；同一个数据目录只运行一个实例。
