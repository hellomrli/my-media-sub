# TMDB 剧名匹配与自动重试

本页描述 v2.7.7 的剧名匹配增强。它延续现有标题清洗，并在 TMDB 没有结果时继续调整搜索词；不是基于大模型的猜名服务。

## 在订阅编辑器中使用

1. 在系统设置中选择 TMDB，配置 API Key，并用测试按钮确认服务端可以访问 TMDB。
2. 新建或编辑订阅，填写剧名。点击「智能识别剧名」，或离开剧名输入框，先清理字幕组、画质、年份与季集标记，再匹配元数据。
3. 第一次查询为空时，服务端按顺序尝试标题变体。匹配区域会显示结果，以及已经尝试的名称；也可以点「匹配」重新查询。
4. 命中后，尚未选择元数据的表单自动应用首个排序结果的标准标题。已有选择不会被自动覆盖，可点击其他候选手工更换。

清洗与搜索串行执行。所有候选都为空时保留清洗后的输入，不把试探词写入订阅名；只点击「匹配」而未清洗时，失败也不改变原输入。重复查询同一个在途请求会合并；改名、切换表单或关闭对话框后，迟到的结果不能覆盖当前编辑内容。

原始分享标题保留在 `source_title`。已识别的年份继续参与同名翻拍排序，季度提示不会覆盖手工选择的 `2`、`1-4` 或 `1,3`。反复识别已经清洗的标题不会清空原来的年份提示。

## 会尝试哪些调整

第一条查询始终使用现有清洗器的结果。后续候选依据当前标题，以及与它对应的原始分享标题生成，去重后最多保留 6 个（包含第一次查询）。

| 情况 | 输入示例 | 后续候选示例 |
|---|---|---|
| 系列篇章未单独建档 | `凡人修仙传之星海飞驰篇` | `凡人修仙传` |
| 双语分享标题 | `未知译名 / Known English Title` | `Known English Title` |
| 明示别名 | `未知译名（又名：正确剧名）` | `正确剧名` |
| 书名号内是主标题 | `《凡人修仙传》星海飞驰篇` | `凡人修仙传` |
| 分类前缀被标点粘住 | `国漫：凡人修仙传` | `凡人修仙传` |
| 中文字间多余空格 | `庆 余 年` | `庆余年` |
| 系列副标题有明确边界 | `Story - A New Beginning` | `Story` |

这些是候选生成示例，不承诺 TMDB 一定存在对应记录。只在类型为 `series` 或 `anime` 时去掉篇章或副标题；电影不会用这一规则丢掉副标题。不会任意删词，也不会截断日文假名或续集数字，例如 `鬼滅の刃`、`四月は君の嘘`、`请回答1988`、`1917` 和 `三体 II`。

`source_title` 清洗后的标题必须与当前查询一致才会提供别名。手工改为另一部剧后，不再拿旧分享标题的别名来搜索。

## 何时停止

- 只有 TMDB **成功响应且没有可用媒体结果**，才尝试下一个标题。
- 取得第一组非空候选立即停止，不把不同查询的结果混在一起。沿用类型、标题相似度和年份排序；仍应核对同名作品，不保证首项就是目标剧。
- 最多查询 6 个去重标题，共用 30 秒的**标题查询阶段**预算。不是每个标题各等 30 秒。
- 查询命中后才补充 TV 详情、季度与剧集信息。详情补充保留原有超时与缓存策略，**不包含在上述 30 秒预算内**，整体请求可能更久。
- Key 缺失、鉴权失败、限流、网络故障或其他上游错误直接结束，不伪装成「没有结果」后继续改名。

后台元数据刮削使用同一个服务入口，并用实际命中的查询词选择候选。它不会把中间试探词写成订阅名称。没有配置 TMDB 时仍可添加普通分享订阅。

## API 兼容性

`GET /api/metadata/search` 保留 `ok` / `data` 数组信封，增加搜索过程字段。旧客户端可继续只读取 `data`。

| 查询参数 | 用途 |
|---|---|
| `query` | 必填，当前剧名或分享标题 |
| `media_type` | 可选；`movie`、`series`、`anime`，其他值走多类型搜索 |
| `year` | 可选，1900–2100 的年份排序提示；无有效值时从 `query` 提取 |
| `source_title` | 可选，恢复别名所需的原始标题；不覆盖当前查询 |

全部候选为空的响应示例：

```json
{
  "ok": true,
  "data": [],
  "message": "已尝试 2 个剧名，仍未匹配到元数据：星海旅人之远航篇 / 星海旅人",
  "attempted_queries": ["星海旅人之远航篇", "星海旅人"],
  "matched_query": null
}
```

命中时，`data` 为媒体候选数组，`matched_query` 为实际查到数据的搜索词；它不一定等于 TMDB 返回的标准标题。`attempted_queries` 只包含实际执行的查询，不列出尚未使用的变体。元数据提供方设为 `none` 时，这两个字段分别为 `[]` 和 `null`。

错误仍使用统一错误信封，不返回一个伪成功的空数组。完整结构见 [OpenAPI](../static/openapi.json) 与 [API 契约](api-contract.md)。

## 仍然匹配不到

先区分「没有结果」与「请求失败」。前者可以试试 TMDB 收录的原名、另一种译名或不含篇章的系列主名；后者先检查 Key、服务端网络和 TMDB 状态，不要反复换词。补充年份有助于区分同名翻拍，但不会创造 TMDB 中不存在的条目。
