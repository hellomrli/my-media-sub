# v2.7.4 升级指南

## 升级方式

```bash
docker compose pull
docker compose up -d
docker compose logs --tail=100 -f
```

固定版本部署请使用 `ghcr.io/hellomrli/my-media-sub:2.7.4`。

二进制部署请使用 v2.7.4 Release 中的 Linux x86_64 归档，校验 SHA-256，停止旧进程后同时替换二进制和整个 `static/` 目录，再重新启动。不要让两个实例同时使用同一个 `DATA_DIR`。

## 数据与接口兼容性

- 本版本不修改 API 或 JSON Store schema，信封版本仍为 **2**；可直接复用 v2.7.2 的 `data/` 和配置，无需手工迁移。
- 回滚到 v2.7.2 不需要转换数据。若从更早的版本升级，仍需阅读 [v2.7.2 升级指南](upgrade-v2.7.2.md) 中关于 Token scope、schema v2 和旧版回滚的说明。
- 前端资源 URL 带有 `?v=2.7.4`，PWA 缓存代次同步更新。二进制用户必须一并部署新 `static/`，避免继续加载旧资源。

## 依赖与构建要求

| 依赖 | 原版本 | 新版本 |
| --- | --- | --- |
| tokio | 1.53.1 | 1.53.2 |
| libc | 0.2.189 | 0.2.190 |
| uuid | 1.26.1 | 1.27.0 |
| base64（直接依赖） | 0.22.1 | 0.23.1 |
| tower-http（直接依赖） | 0.6.11 | 0.7.1 |
| tokio-cron-scheduler | 0.13.0 | 0.15.1 |
| rustls（间接依赖） | 0.23.45 | 0.23.46 |
| yoke-derive（间接依赖） | 0.8.3（已撤回） | 0.8.4 |
| actions/checkout | v6 | v7 |

`rustls` 的补丁修复 RUSTSEC-2026-0346 / 0347 / 0348 / 0349，涵盖会话 Debug 泄漏、ECH 拒绝顺序、Brotli 证书解压内存和密钥交换预测缓存问题。各公告有特定配置和握手条件；本次统一更新到修复版本，不增加审计忽略项。

**从源码构建至少需要 Rust 1.89**，开发工具链仍固定为 1.97.0。`uuid` 1.27 明确要求 1.89，而更新前锁文件中的 ICU 2.3 已要求 1.88，旧的 `rust-version = "1.87"` 声明已偏低。本次如实更新声明，并增加使用最低版本实际编译的 CI job。

此要求只影响源码构建，不要求二进制或 Docker 用户安装 Rust，也不改变现有发布二进制的 glibc 构建基线。

`p256` 0.14 涉及随机源与公钥编码 API 迁移，本次保持 0.13.2，不为追求版本号引入未经迁移验证的密码学改动。`base64` 0.22 和 `tower-http` 0.6 仍被部分间接依赖使用，锁文件保留两代版本是正常现象。

完整变更见 [CHANGELOG.md](../CHANGELOG.md) 的 `## 2.7.4` 段。
