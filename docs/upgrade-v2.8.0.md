# v2.8.0 升级指南

v2.8.0 不修改 JSON Store schema，可直接复用 v2.7.7 的数据与配置。升级前核对备份，保留 `data/`、`runtime/` 和原 `.env`；不要用新安装命令覆盖现有管理员密码。

## Docker Compose

在原部署目录执行：

```bash
docker compose pull
docker compose up -d
docker compose logs --tail=100
curl --fail http://127.0.0.1:56001/health
```

确认健康检查返回 `"version":"2.8.0"`。固定镜像版本的用户应改为 `ghcr.io/hellomrli/my-media-sub:2.8.0`。

建议拉取镜像并重建容器，而不只执行 WebUI 在线更新：在线更新替换程序与静态资源，不能更新容器基础层的系统软件包。新版镜像构建继续获取基础镜像与运行层补丁，保留 bookworm 二进制兼容性。

## 独立二进制与在线更新

从 [v2.8.0 Release](https://github.com/hellomrli/my-media-sub/releases/tag/v2.8.0) 下载 Linux x86_64 归档和同名 SHA-256 文件，校验后停服替换程序与**完整 `static/` 目录**，保留数据、配置和备份。命令见 [部署参考](usage.md#快速安装)，在线更新的信任与签名要求见 [Docker 在线更新](docker-online-update.md)。

不要只换二进制。字体、页面资源 URL 与 Service Worker 缓存代次同时更新为 2.8.0，升级后重新加载旧页面。已有深色主题和表格偏好继续保留；没有偏好时默认浅色与海报墙。

## 行为变化

- **新增电影改为一次保存**：选择“电影”后选择画质与具体正片，再执行下载保存，不创建持续追更订阅。已配置 Aria2 时默认同时下载，也可仅保存网盘；电影目录不添加 `Season N`。
- **旧电影保留但停止定时追更**：原订阅、进度与手动操作仍在，已有后台任务不自动取消。需要继续保存资源时使用新电影流程。
- **剧集可固定画质**：原规则没有 `preferred_resolution` 时仍为自动择优；选择 1080P / 4K 后，后续检查、补转、重命名与换源只处理所选画质。当前没有该画质时等待，不静默降级。
- **改画质不替换已保存集数**：已有进度和转存历史保持不变，新选择只影响后续处理；要替换旧版本需另行保存或手动处理。
- **保存结果与下载结果分开核验**：云端保存成功后才提交本地下载，下载失败不会撤销已保存文件。有保存证据的任务禁止再次重试转存；先核对下载管理，再从网盘页继续下载。
- **命名探测而非码流检测**：识别文件名和画质目录中的分辨率标记，同画质的多个电影版本分别列出；未标注资源显示未知，预告与花絮不作为正片。大型分享或目录读取失败会显示探测不完整。
- **旧 API 兼容**：`/api/transfer` 省略 `save_options` 时仍是原整份分享转存；新表单显式提交所选文件。新响应字段与请求示例见 [电影保存与画质选择](media-save-quality.md)。

## 升级后核验

1. 确认 `/health` 返回 2.8.0，原订阅、任务、设置和主题偏好仍在。
2. 使用实际多画质电影分享，分别选择 1080P / 4K，核对正片文件名与大小；先试仅保存到网盘，再验证 Aria2 下载与所选文件一致。已有同名文件时应停止，而不是下载旧版本。
3. 用实际剧集分享设置固定画质，检查预览和后续更新是否只处理对应版本；换源候选缺少该画质时不能应用。
4. 确认旧电影不再参与周期追更，手动检查与既有记录仍可查看。

自动回归使用测试 Provider 和下载器夹具，不包含真实夸克账号与 Aria2 的端到端验证；请在自己的部署环境完成第 2、3 项。

## 回滚

先停止新任务提交，等待或取消所有新的电影保存任务，核对已经保存的文件与下载状态，再停服并保存当前数据副本。旧版手动转存不理解 `save_options`，未完成的电影保存任务不能交给旧程序执行，否则可能按整份分享转存。

换回旧镜像或旧二进制与配套静态资源，必要时恢复升级前备份。旧版不执行固定画质规则，且会恢复旧电影的周期追更行为；回滚后先核对订阅启用状态。不要让两个实例同时使用一个数据目录。
