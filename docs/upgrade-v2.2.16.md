# v2.2.16 升级指南

Docker Compose 部署：

```bash
docker compose pull
docker compose up -d
docker compose logs --tail=100 -f
```

如果 Compose 文件固定了镜像版本，请先把镜像标签改为 `ghcr.io/hellomrli/my-media-sub:2.2.16`，再执行上述命令。

v2.2.16 不修改 JSON Store schema，可直接复用 v2.2.15 的 `data/`，无需任何迁移动作。

## 本版本修了什么

**换源的「确认应用」按钮此前点不动。** 搜索出候选之后，每个候选的应用按钮都是灰的——按钮的禁用条件要求「这个候选已经有预览且探测成功」，而刚搜出来的候选一个预览都没有。矛盾之处在于，应用函数本身就会在缺少预览时先自动探测再应用，禁用条件把它唯一能走的入口堵死了。升级后按钮默认可点，点击会自动完成探测；只有正在应用、正在探测，或预览已判定季度不匹配（这一条强制应用也不可越过）时才禁用。此前探测失败过一次的候选按钮会永久失效，现在会重新探测。

**夸克的网络抖动此前会被当成订阅失效。** 偶发的 `请求夸克 token 失败: error sending request for url ...` 属于连接层故障，和分享链接本身没有关系，但此前会走完整的失效流程：把订阅标为失效、累加失效计数、推送「订阅链接疑似失效」通知，如果开启了自动换源，还会把一个完全可用的来源换掉。现在分两层处理：

- 幂等请求（取 token、列分享文件、各类 GET）遇到连接失败、超时、请求发送失败或上游 5xx，会以 300ms 起的指数退避重试 3 次；
- 重试后仍失败的探测按故障类型区分，网络类（`error`）和限速（`rate_limited`）只在订阅上记一条「来源暂时不可用，将在下次检查重试」，不改状态、不计数、不触发换源；只有分享确实被取消（`bad`）或需要提取码（`locked`）才判失效。

转存、重命名、删除这类有副作用的请求不参与重试，避免超时重放造成重复操作。

**部分已完结的订阅停留在「追更中」。** 涉及三个独立的漏洞：

1. **电影订阅永远无法完结。** 完结判定依赖「目标集数」，而电影没有集数，因此转存完成后也拿不到完结条件。现在电影拿到正片文件即视为完结。**升级后，已经转存过正片的电影订阅会在下一次检查时移入「已完结」并停止检查**——如果你希望某部电影继续追更（例如等更好的版本），用订阅菜单里的「重新追更」恢复即可。
2. **后补的元数据集数没有回落到订阅上。** 订阅创建时往往还没刮削到元数据，之后补上的季集数如果不写进 `total_episode_number`，完结判定就永远没有目标。现在会自动回填（多季订阅没有单一总集数，跳过）。
3. **关闭了自动转存的订阅等不到转存证据。** 这类订阅此前只看已转存文件，永远无法满足完结条件，现在改用已发现的集数判定。

另外每轮检查写回后会用最新记录再核对一次完结状态，并修正历史数据中 `completed=true` 但 `status="active"` 的不一致。

**新增手动开关。** 订阅操作菜单里多了「标记完结 / 重新追更」。完结判定依赖总集数和文件名解析，两者都可能缺失或误判；手动设置时以你的判断为准，不会被自动推导改回去。

## 移动端与响应式

这一版对各分辨率做了一轮系统排查：用 CDP 脚本在 320 / 390 / 768 / 1024 / 1280 / 1920 / 2560 七档宽度逐页扫描溢出视口的元素、意外的横向滚动容器和过小的触摸目标。修复项：

- **订阅、下载任务、活动中心三张数据表在窄屏（<1024px）改为卡片堆叠。** 这三张表的固定列宽合计接近 1000px，此前在手机和平板上必须横向滚动才能看到状态、最近检查和操作列，而移动端的横向滚动条没有视觉提示，等同于这些列不存在。
- **同样三张表在 1024–1400px 会把「操作」列挤出可视区**（侧边栏占 256px），桌面列宽改为可伸缩定义，从 1024px 到超宽屏都能完整显示。
- **更新日历在 <768px 默认切换为列表视图。** 周视图是 7 列 × 145px 的网格，手机上只能横向滚动一屏空格子。
- 订阅详情页移动端底部操作条此前被负外边距推出容器、「打开分享」有一半在屏幕外；设置页「配置完成度」圆环内的文字溢出圆环边缘——两处均已修复。
- 活动中心筛选按钮组窄屏改为换行；触摸设备上过小的点击区域（文字按钮、小图标按钮、复选框、日历条目按钮）统一放大到 34–36px；移动端主内容区补上 iOS 底部安全区。

## 二进制部署

手动升级时必须同时替换归档中的整个 `static/` 目录；只替换二进制会继续运行旧前端代码。前端资源 URL 带有 `?v=2.2.16`，Service Worker 缓存代次为 `v2.2.16-responsive-and-source-switch-1`，浏览器会在下次打开时提示「新版本静态资源已就绪」。

普通 Linux 二进制部署可继续使用 WebUI 的在线升级（「系统设置 → 维护 → 在线更新」），升级器会校验 SHA256 并把二进制与完整 `static/` 作为同一个可回滚事务替换。

## 需要注意

- 本版本没有新增依赖，也没有改动 `Cargo.lock` 的依赖树，只有包版本号本身变化。
- `PUT /api/subscriptions/{id}` 新增可选字段 `completed`（布尔）。显式传入时以该值为准并跳过自动推导；不传时行为与此前完全一致，现有调用方无需改动。
