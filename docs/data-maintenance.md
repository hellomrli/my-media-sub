# 备份、升级和恢复数据

[返回文档入口](index.md) · [部署指南](deployment.md)

## 确认持久化目录

同一个 `DATA_DIR` 只运行一个实例。业务数据使用带 `schema_version` 的 JSON Store，不需要外部数据库：

```text
DATA_DIR/
  settings.json          subscriptions.json     notifications.json
  jobs.json              jobs.archive.json      automation_events.json
  automation-token.json  telegram_bot.json      backups/
```

Docker 另有 `runtime/`，保存实际程序和 WebUI。迁移或容器重建时保留两个目录。容量规划、保留门槛与数据库迁移决策见 [存储扩展](storage-scaling.md)。

## 创建和核对备份

1. 在设置的维护页创建备份或导出完整数据归档。配置定时备份后仍需检查最近成功时间。
2. 查看备份校验结果与文件清单，将升级前的归档另存到受保护的位置。
3. 记录当前版本、部署方式和数据目录；跨版本恢复前阅读相应升级指南。

`BACKUP_MAX_STORAGE_MB` 限制轮换后保留的本地归档总大小。系统先写入新归档并在隔离目录验证恢复，再按容量和 `BACKUP_RETENTION` 清理旧副本。请为新旧归档并存和隔离恢复预留临时空间；单份归档超出预算、写入失败或校验失败时，不会为了腾空间而删除已有备份。

备份包含 Cookie、Token 和其他配置凭据，限制访问并加密保存。自动化 Bearer Token 无权导出或恢复完整备份；这类操作使用管理员认证。

需要一致的文件级副本时，先停服再复制数据和运行目录。不要把正在写入的多个 Store 文件当作同一时刻的完整快照。

## 执行升级

- Docker 通过 WebUI 切换 Release 时，按 [在线更新步骤](docker-online-update.md) 核对可写目录、SHA-256 和可选 minisign 签名。
- 拉取新镜像并重建容器时，保持 `data/` 与 `runtime/` 挂载。镜像载荷变化会刷新 runtime；载荷相同的重建保留在线更新结果。
- 独立二进制部署先停服，同时替换程序和完整 `static/`，再使用原数据与配置启动。
- 检查 `/health`、设置、订阅、任务与界面版本。PWA 缓存问题按 [移动端排错](pwa.md#故障排查) 处理。

程序在线更新不会更新容器基础镜像和系统库；需要系统补丁时拉取镜像并重建。回滚是否需要恢复升级前的业务备份，以 [版本升级指南](index.md#升级指南) 为准。

## 恢复完整归档

1. 使用管理员身份预览归档，核对路径、schema、大小与校验结果。
2. 确认后输入精确文本 `RESTORE DATA`。系统校验并暂存归档，执行前创建当前快照。
3. 尽快重启服务。归档在下一次启动、加载 Store 与后台任务之前应用；重启前继续修改的数据会被备份覆盖。
4. 启动后核对健康检查、设置、订阅数量与最近任务。

应用恢复失败时会回滚并停止启动，保留暂存文件以便排查和重试。不要通过删除 Store 让服务看起来恢复正常。

`DATA_DIR/.lock` 属于运行中的实例，不随数据导出。旧版归档中若有此文件，预览会提示，恢复和回滚都不会替换当前实例锁。

## 恢复损坏的 Store

损坏文件会隔离为 `*.json.corrupt-*`，诊断页保留提示。默认中止启动；容器自动重启不会绕过这一保护。

1. 停服并保留原目录、隔离副本和日志。
2. 从已核对的备份恢复原路径的有效 Store，确认内容和 schema 兼容。
3. 重启并查看诊断；恢复有效文件后可以继续保留隔离副本，不影响启动。
4. 确认数据正确后再决定是否清理隔离文件。

`ALLOW_QUARANTINE_STARTUP=true` 会显式允许受保护的业务 Store 以空数据启动，意味着接受当前数据缺失，不能代替恢复。设置存储不接受此放行，以免重新生成凭据和密钥。

Store 的临时文件、fsync、原子 rename、保存锁和 Unix `0600` 权限合同见 [持久化架构](architecture.md#持久化与恢复)。落盘成功后才更新内存；取消请求不会让旧快照覆盖后续提交。

在线更新的二进制和静态资源分别切换，存在旧程序短暂配合新 WebUI 的窗口。失败回滚与兼容要求见 [Docker 在线更新](docker-online-update.md)。
